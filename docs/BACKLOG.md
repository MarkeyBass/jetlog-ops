- **"Admitted only in lounge …" as a deny reason** (Mark, 2026-10-14, after task 21). When no rule matches at the station's lounge but the pass would match a rule in other lounges, report a new reason (e.g. `OTHER_LOUNGE_ONLY`, "Admitted only in lounges A, VIP") instead of `NO_MATCHING_RULE`. Decided: **the entry stores only the reason code** (and its own `lounge_id`, as today), never the lounge list; the list's current codes are **recomputed whenever the entry is shown**, so a re-code never leaves a stale name. **Shown during the scan, to the operator** (Mark, 2026-10-14): the denied card says where the pass *would* be admitted, so the operator can tell the customer, e.g. "Not admitted in VIP — admitted in lounges A, B". Still open: where it sits in `DENY_REASON_ORDER`; whether the scan response carries the lounge list (the card needs it at scan time); and how the card words it. Decided (Mark, 2026-10-14): "admitted elsewhere" **counts clubs as well as lounges** (a lounge that admits the pass only with a club card is listed, saying which club), and the list is **shown even when another reason also fails** (e.g. `ALREADY_ENTERED`).

- **User-facing wording and small UX fixes** (found by `user-guide-writer` while writing the first user guide, 2026-10-15). The guide documents today's behaviour; update it when any of these is fixed.
  - The log's title "Today's entries" — it shows the 50 most recent hosts from any day, and the Time column shows only the time.
  - Internal names and ids in messages: the rule editor's 409 shows the id-spelled key (`6H-J-#-#-#-3`); bulk clash/delete errors list rule ids the list doesn't show; global-rule errors name internal keys (`max_days_before_departure`) instead of the screen labels; import row errors say `guestPolicy`/`frequentFlyer`/`companyVar` where the CSV columns are `guest_policy`/`frequent_flyer`/`company_var`; a station whose lounge was deactivated gets "lounge N is not an active lounge".
  - Guest policy labels: "Any" in the rules list, "Any guest" in the editor; a new rule starts with **Same carrier** while the system default is ANY.
  - A USB scan made while a result card is on screen is lost (the scan input is gone until **New scan**).
  - The club question only comes when every other check passes, so a pass that fails another check and needs a club also shows "No matching entry rule".
  - An import row skipped because an active rule has its key gives no hint when its description, guests or policy differ (by design — the import never overwrites — but admins may expect an update).
